## Стенд и границы доказательства

Используется существующий Playwright-стенд: отдельная production-сборка frontend, настоящий Go backend на `127.0.0.1:18089`, UI на `127.0.0.1:4179` и новая SQLite в `%TEMP%/dengovod-e2e-*` на каждый запуск. `DATABASE_PATH` заменяется сгенерированным путём. Пользовательская БД и живые серверы 5173/8080 не используются, чужие процессы не останавливаются.

В финансовых сценариях часы сервера не меняются. Через настоящий API создаётся прошлый якорь и прошлые/текущие/будущие day-cost-overrides. Проверяются ручные арифметические ожидания по новой модели, UI, календарь, баланс и forecast; production-алгоритмы в QA не импортируются. Проверено, что изменение стоимости дня не создаёт событий. Локально использованы Playwright 1.65.1 и установленный Chrome 158.0.8127.36 через `E2E_BROWSER_CHANNEL=chrome`; это отдельный браузер без пользовательского Chrome-профиля. Такой fallback сохранён после прежнего сбоя загрузки штатного Chromium по сети.

Переход финансового дня backend через московскую полночь здесь **не эмулируется**: production-сервер не предоставляет контролируемый clock, добавлять backdoor нельзя. Проверки реального финансового перехода 20:59:59Z → 21:00:00Z относятся к независимым API/доменным тестам с fake Now. Браузерные clock-сценарии ниже доказывают только автоматические повторные обращения к настоящему API и сохранность выбора пользователя. Сигнал focus генерируется как DOM event и не выдаётся за реальный сон ОС или полноценный переход финансового серверного дня.

## Пройденные сценарии

- Прошлый выбранный день: якорь позавчера 20000 ₽ и многодневная стоимость 1400 ₽ дают текущий остаток 17200 ₽. Изменение вчера на 1000 → 17600 ₽, MFL 16200 ₽. Затем через API добавляется **более поздний** перекрывающийся период вчера–завтра по 2000 ₽: текущий остаток 16600 ₽, MFL 14600 ₽. После этого повторное редактирование выбранного дня новым POST на 0 → текущий остаток 18600 ₽, MFL 16600 ₽; ещё один POST на 700 → остаток 17900 ₽, MFL 15900 ₽. Таким образом проверяется приоритет свежего правила, а не только редактирование поверх старого периода. Проверены pending с удержанным **реальным** ответом, блокировка повторного сохранения, обновление UI без reload, согласованность API и сохранение после reload. Оба многодневных правила остаются неизменными; соседние дни сохраняют соответствующую им стоимость (позавчера 1400, сегодня 2000).
- Будущий выбранный день: 1400 → 0 → 900 меняет ожидаемый конец будущего дня, но текущий остаток остаётся 17200 ₽. Дополнительный override другого периода сохраняется без изменений. Проверяется reload.
- Без первого якоря: ошибка соединения до отправки запроса в backend сохраняет введённые 1000 ₽ и показывает ошибку; затем настоящий повтор успешен, последующее изменение на ноль сохраняется после reload. Баланс/summary до якоря остаются неизвестными, событий нет. HTTP-ответы API не подменяются фикстурами.
- Таймер browser clock пересекает московскую полночь: balance/forecast/calendar получают новые успешные реальные GET, выбранные октябрь и 15 октября сохраняются; «Сегодня» затем открывает декабрь и подсветку 1 декабря.
- DOM-сигнал focus после перевода browser Date: balance/forecast/calendar запрашиваются повторно, выбранные месяц/дата сохраняются.

Desktop использует 1440×1000. Mobile стартует в 390×844; в сценариях редактирования выполняется resize до 320×844 перед нулём/повторным изменением и проверяется отсутствие горизонтальной прокрутки. На обеих ширинах сохранены и визуально проверены фрагменты редактора и текущего остатка. Число проектов не увеличено, старые сценарии и их ожидания не менялись: их текущие якоря и нулевые/сегодняшние дневные затраты остаются совместимы с DV-8.
