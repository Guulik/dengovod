## Полномочия и роли

Техлид принимает архитектурные и технические решения, утверждает ТЗ, интегрирует изменения и ведёт отчёт. Пользователю выносятся существенные изменения сценариев и восприятия продукта. Решение продукта от 2026-11-15: разделить план и факт, подтверждать конкретное вхождение повторяющейся операции.

Backend reviewer и frontend reviewer: два существующих чата. Работают только на чтение, предлагают варианты, проверяют конкретный diff и подтверждают устранение находок. Исполнители backend/frontend: реализация по утверждённому ТЗ и собственные юнит-тесты. QA business: независимые бизнес-тесты API и домена. QA e2e: проверка полного пути в браузере, включая мобильный экран.

## Цикл поставки

1. Ревью проблемы → решение техлида → записанное ТЗ и критерии приёмки.
2. Реализация и юнит-тесты исполнителя.
3. Независимые тесты бизнес-сценариев и e2e.
4. Повторное backend/frontend ревью конкретного состояния.
5. Исправления → повтор затронутых тестов и ревью до отсутствия значимых проблем.
6. Интеграция, публикация ветки, закрытие issues с коммитами и доказательствами проверки.

P0/P1 и влияющие на сценарии P2 блокируют поставку. Нельзя закрывать issue только потому, что код написан. Пропущенные или невозможные проверки явно фиксируются. Новые P2 вне сценариев бэклога оценивает техлид и записывает решение.

Ветки: архитектура `release/A-<номер>`, функции `release/DV-<issue>`, прочие `fix/<смысл>` и `test/<смысл>`. При тесно связанных #1 и #4 допустима общая feature-ветка с явными ссылками на оба issue. Коммиты базового снимка, инфраструктуры, функций и независимых тестов разделять.
